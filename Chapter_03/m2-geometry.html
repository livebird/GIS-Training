Module 3.2 · General GIS idea

Point, line, polygon: shapes made of vertices

Every shape in a GIS is a list of stored positions and a rule for reading the list. Once you see that, “point”, “line” and “polygon” stop being mysterious — and so does the difference between a thick drawn line and a wide real road.

In this module you will

  • Build points, lines and polygons from vertices and segments, and count them.
  • See why the thickness of a drawn road line has nothing to do with the road’s real width — and when you need an area instead.
  • Meet the four numbers a vertex can carry — X, Y, Z, M — and learn that file formats disagree about which are allowed.

3.2.1Three shapes, one building block

A vertex is one stored position — in our town, an (x, y) pair in metres. (Plural: vertices.) That is the only building block.

Two facts that follow directly from the lists

R2 has 3 vertices, so 2 segments: 500 m straight up, then 500 m diagonally (Δx 300, Δy 400 → √(300² + 400²) = 500). Total 1,000 m. A line’s length is the sum of its segments — not the straight distance between its ends (that would be about 949 m).
Ward A has 4 corners but 5 stored vertices, because the ring repeats its first vertex to close. Its area — 1,000,000 m² — is a property of the ring, not of any vertex.

One shape type per collection

Both ArcGIS and QGIS keep every feature in one dataset the same shape type: a “feature class” or “layer” is all points, or all lines, or all polygons, with one common set of columns. That is why the school is stored twice (module 3.1) — a points dataset and a polygons dataset — never both shapes in one. ArcGIS also has a few special types (multipoint, multipatch for 3D shells, annotation) that you only need to recognise by name in Phase 1.

Developer view

A line is an ordered array of points; a polygon is such an array with the rule first == last. Think of moveTo / lineTo calls. Where the comparison stops: in a drawing API the path is the thing. In GIS the segments between vertices are also geometry: “distance from P1 to the road” is measured to the nearest point on a segment — P1’s 300 m lands at (200, 500), which is not a stored vertex at all.

The bus loop L1 stores the vertices (1300, 300), (1350, 300), (1350, 350), (1300, 350), (1300, 300). How many segments does it have, and how long is it?

3.2.2A thick drawn line is not a wide road

Road R1 is stored as a segment with zero width — a line has length but no width. On the map it is drawn with a symbol: a stroke of some thickness and colour. That thickness is a display choice. The road’s real width is a separate fact in the column width_m (12 m for R1).

Symbol thickness is usually given in points (pt) — a printing unit; 1 pt ≈ 0.353 mm on paper or screen. How many metres of ground that stroke seems to cover depends only on the map scale. Play with both:

Try it

Keep a line when the question is about…

  • connection: “which roads cross the ward boundary?”
  • length: “how long is Station Road?” (1,000 m)
  • nearness: “which complaints are within 300 m of R1?”
  • position along the road: “the pothole 800 m from the start”

You need an area (polygon) when the question is about…

  • the surface itself: “how many m² of asphalt need resurfacing?”
  • overlap: “does the proposed kiosk stand on the carriageway?”
  • the edge: “which side of the kerb is the drain on?”
  • a junction, a bus bay, a widening — shapes a line cannot hold

Length × width_m gives a rough estimate (R1: 2,000 × 12 = 24,000 m²) but double-counts junctions and misses every widening.

Misconception

“I set the road symbol to 12 metres wide in real-world units, so the map now shows the true road.” The symbol scales correctly, but it is still centred on a centreline and still cannot show a lay-by or a median. It is a nicer picture, not a measurement.

So a road with M values in a geodatabase or PostGIS cannot be saved as GeoJSON without losing M. Chapter 7 covers such conversion checks; the lesson now is that “a coordinate” is not one fixed thing.

Developer view

X, Y, Z, M are like tuple types: (float, float), (float, float, float), (float, float, float, float). A schema that accepts only 2-tuples rejects or truncates a 4-tuple. Where the comparison stops: Z and M are not interchangeable “third numbers” — Z is a spatial axis with a vertical reference (Chapter 5); M is not spatial at all. Read the third number with the format’s rule, never by guessing.

A supplier sends streetlights as GeoJSON with three numbers per position and says the third is “distance from the start of the street”. What is wrong?
Misconception

“If a vertex has a Z, the dataset is 3D.” A Z per vertex gives each vertex a height. It does not give a point a roof or a footprint walls. True solids are a different shape type (Esri’s multipatch) and are outside Phase 1. Module 3.9 has a small 3D sketch of exactly this point.
