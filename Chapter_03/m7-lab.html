Module 3.7 · Guided lab

Model and inspect a small town

You get a made-up town as data. You will justify every shape choice, write an intake record, show one dataset two ways without changing it, and point at the one dataset that cannot answer its question. Your answers are saved in this browser; the deliverables go to your instructor.

Objective and prerequisites

  • Modules 3.1–3.6 read; the Chapter 1 map walk-through done or read.
  • Software: ArcGIS Pro (primary route) or QGIS 3.40+ (route in 3.7.7). No software? Use the paper route (3.7.8) — it covers every outcome except the “observed in software” part.
  • No coordinate-system knowledge needed. The software will say the data has an unknown coordinate system. That is correct — do not “fix” it. Chapter 5 explains why.
Honesty note

The steps below were written from the official ArcGIS Pro (3.7) and QGIS (3.40) documentation and have not been run by the author. Expected results are hand-checked from the tables, not observed on screen. Your instructor builds and verifies the data package before the session; if a button or label differs in your installed version, note it in your log.

3.7.2The data package (synthetic)

Ten small text files. Lines and areas are written as WKT in a wkt column (module 3.3); points have x and y columns. The instructor turns these into Chapter03_Town.gpkg (a GeoPackage) or a file geodatabase. Download the files here to read them — you can open a CSV in any text editor or spreadsheet.

Flat practice grid in metres, (x, y), y upward, no coordinate reference system. Not a real place. P7 has blank coordinates on purpose. The value Closed - duplicate uses a plain hyphen in the file.

3.7.3Steps (ArcGIS Pro primary route)

Keep a lab log. Write every observation as you make it: “I expected …” and “I saw …” are both required.

  1. 1
    Open the prepared project Chapter03_Town.aprx (or make a new map and add every feature class from the GeoPackage — ArcGIS Pro reads GeoPackage directly). The map reports an unknown coordinate system. Do not set one.
  2. 2
    Justify the shapes before touching the software further: complete deliverable A below for all ten datasets.
  3. 3
    Intake check (module 3.6.2): for each spatial dataset record count, shape type, columns, extent, and rows with no shape. Compare with the expected values (3.7.4). Every difference is either a build error (report it) or a misunderstanding (resolve it). Do not continue with an unexplained difference.
  4. 4
    Find the structural exceptions. Open the tables of Parks and Depot: one row each. Zoom to Parks: what does one row look like? Zoom to Depot and click inside the courtyard with the Explore tool: does a pop-up for DP-01 appear? Click the depot ring itself and compare. Identify L1: note what the pop-up reports (a length, perhaps; never an area).
  5. 5
    Related records. Select DR-0042 on the map; open the Assets table with Show Selected Records. Open the Inspections stand-alone table and, without any join, find rows with asset_id = 'DR-0042' (sort, or Select By Attributes). Expect 2, in date order.
  6. 6
    Two presentations of one source. Add the Requests feature class to the map a second time. Rename the two layers Requests — by status and Requests — High priority. On the first: Feature Layer ▸ Symbology ▸ Unique Values, Field 1 = status. On the second: Feature Layer ▸ Data ▸ Build Definition Query ▸ New definition query, clause priority = 'High', Apply. Record each layer’s row count and dot count. Then record the source dataset’s count from the Catalog pane or Get Count on the feature class with no selection.
  7. 7
    Drawing order. Drag Wards (solid fill) to the top of the Contents pane. Count visible complaints. Drag it to the bottom. Count again.
  8. 8
    Presentation change vs geometry edit. Make Requests_scratch with Copy Features (no selection active). Write the five predictions of module 3.6.3 in your log. On the scratch copy: Edit ▸ Modify ▸ Move, move P1 to (200, 300), Finish. Check the predictions. Edit ▸ Discard. Confirm the original still has P1 at (200, 200) and 7 rows.
  9. 9
    The unsuitable representation. Using only Wards_as_points, try to answer “which ward is P3 in?”. Write why it cannot, what it could answer, and what is needed.
  10. 10
    Close without saving edits. Save the project if you like (settings only). Reopen: 7 requests, P1 at (200, 200).

3.7.7QGIS route (same results; not execution-tested)

  • Adding data: Layer ▸ Add Layer ▸ Add Vector Layer for the GeoPackage. For the CSV route, Add Delimited Text Layer offers “Point coordinates” (X/Y fields) or “Well known text (WKT)”, and asks for a Geometry CRS — your instructor will tell you what to choose so the layer stays without an Earth reference.
  • Intake: Layer Properties ▸ Information tab (geometry type, extent, feature count, fields); attribute-table title bar for counts. QGIS may report Parks as MultiPolygon — still a polygon layer; record what you see.
  • Two presentations: right-click ▸ Duplicate Layer. Symbology ▸ Categorized on status, Classify; on the duplicate, Filter… with "priority" = 'High'. Check the source count from a third, unfiltered layer or the Browser panel.
  • Drawing order: drag in the Layers panel; the layer nearer the top draws over those below.
  • Scratch copy and move: Export ▸ Save Features As… to a new GeoPackage layer; Toggle Editing; Move Feature(s); then Save Layer Edits or cancel.
  • Identify: Identify Features tool; a click in the courtyard should identify nothing from Depot if the hole survived the build.

Do not claim QGIS and ArcGIS Pro produce identical pictures (default symbols, pop-ups and area/length column names differ). Claim only that counts, types, extents and the invariant agree — and record any that do not.
