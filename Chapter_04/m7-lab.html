Module 4.7 · Guided lab · ArcGIS Pro (primary) or QGIS 3.44

Lab: inspect two rasters

Type two tiny raster files, load them, read their properties, change how they look without changing a value, resample copies two ways, and write down the numbers. Every expected number on this page was worked out by hand from the listings; your job is to make the software show them — and to record what it does where the documentation does not say.

Before you start

  • You have finished modules 4.1–4.6.
  • You have ArcGIS Pro (any licence level) or QGIS 3.44. No extension, no account, no credits.
  • No software? Steps 1–3 and the statistics can be done by hand; write your predictions for the resampling steps and the instructor will confirm them.
Honesty note

The author has not run these steps in ArcGIS Pro or QGIS. The procedure boxes were written from the official documentation (ArcGIS Pro 3.7; QGIS 3.44 user guide; GDAL). If a button or label is not where the box says, use the idea, and note the difference in your discrepancy list — it helps fix the box.

4.7.3Step 0 — Create the two input files

Both files use the Esri ASCII raster format: six header lines, then the values row by row, first row = top row. Make a folder without spaces in its path (e.g. C:\GIS_Training\Ch04\). Use a plain-text editor (Notepad, VS Code) — not Word. Do not create a .prj file; the lab depends on the coordinate system being unknown.

10 lines; 16 values. Metres above the made-up datum TD-0. The decimal points matter: they make the software store the numbers as floating point.

What to expect from a file with no coordinate system

Both programs will tell you the coordinate system is unknown and will draw the raster using its raw numbers (0–1000 m). Where that lands “in the world” is meaningless. Do not add a basemap — a basemap has an Earth coordinate system and the raster would be drawn at raw positions inside it, the silent guess Chapter 5 teaches you to refuse. In QGIS set the project to No CRS, under which “layers are drawn based on their raw coordinates”.

4.7.4The steps

Procedure (version-specific; written from ArcGIS Pro 3.7 documentation; not execution-tested). Tools used — Copy Raster, Resample, Calculate Statistics — are listed as available at the Basic licence on their tool pages.

  1. Empty map. New project from the Map template. In Contents, right-click the basemap → Remove. Save the project in the lab folder.
  2. Add the land-cover file. Map tab → Add Data → browse to landcover_training.asc. ArcGIS Pro reads the ASCII Grid format directly (listed as read-only, .asc). Accept the “unknown coordinate system” warning. You should see a 10 × 10 block of coloured squares. Change nothing yet.
  3. Inspect and fill Table A. In Contents, right-click the layer → Properties → Source. Record columns × rows, bands, cell size, pixel type, NoData value, extent (left, right, bottom, top), spatial reference, and min/max/mean if shown.
  4. Read cells. With the Explore tool, click a cell: a pop-up shows the pixel value (Esri: “click on a pixel. Values for each visible band will be returned”). Use the coordinate readout at the bottom of the map to aim. Fill Table C for the five land-cover positions.
  5. Style without changing values — and prove it. Symbology → Unique Values; give each code the colour and label from the dictionary; set NoData to a loud colour (all renderers allow this). Then re-open Properties → Source: every entry in Table A must be unchanged. Re-read the five cells: unchanged. Write one sentence: what changed (the layer’s renderer) and what did not (the dataset).
  6. Add the elevation file and fill its Table A row. Expected: 4 × 4, 1 band, cell 100, floating point, NoData −9999, extent 0 / 400 / 600 / 1000, spatial reference undefined. If the pixel type says integer, see Troubleshooting. Style with Stretch → Minimum Maximum. Read (50, 950) → 12.0 and (150, 650) → NoData.
  7. Statistics under a stated rule. Properties → Source shows min / max / mean per band; if not, run Calculate Statistics (Data Management) with defaults. Expected for elevation with NoData excluded: min 9.0, max 21.0, mean 13.6. 12.75 → NoData counted as 0. About −612 → the marker was not recognised. Write the statistic as a sentence with rule and coverage.
  8. Resample copies (four runs). Analysis → Tools → Resample (Data Management). Output cell size 50 50; save as TIFF in the lab folder:
    RunInputOutputTechnique
    1elevation_training.ascelevation_50m_nearest.tifNearest
    2elevation_training.ascelevation_50m_bilinear.tifBilinear
    3landcover_training.asclandcover_50m_nearest.tifNearest
    4landcover_training.asclandcover_50m_bilinear.tifBilinear
    The tool page says the extent does not change and the output’s lower-left corner equals the input’s, so expect 8 × 8 and 20 × 20 outputs. The originals are untouched.
  9. Inspect the copies and read the same positions (Tables A and C below). Rows marked record depend on the software — write down whatever appears.
  10. Compare statistics and counts (expected values in the checker below).
  11. Write the explanation: one paragraph per dataset on which resampling result is appropriate and why, citing your recorded numbers; then one sentence on what the 50 m outputs do not contain.

Procedure (version-specific; written from the QGIS 3.44 user guide and GDAL docs; not execution-tested). Same inputs, tables, expected numbers and deliverables. Differences are stated, not assumed away.

  1. Project with no CRS. New project → Project → Properties… → CRS → choose No CRS (or unknown/non-Earth projection). In Settings → Options → CRS and Transforms, the action for a layer without a CRS should be Leave as unknown CRS (or Prompt, then choose no CRS) — not “Use project CRS”. No basemap.
  2. Add the rasters. Layer → Add Layer → Add Raster Layer (Ctrl+Shift+R), File, browse to each .asc. QGIS reads it through GDAL’s AAIGrid driver, which keeps the file’s NoData value and detects floating point when the values carry a decimal point — that is why the elevation file has “.0” everywhere.
  3. Inspect. Right-click layer → Properties → Information: extent, width and height, data type, band statistics, pixel size, NoData values, CRS (will read unknown). Fill Table A.
  4. Read cells. Select the layer, Identify Features (Ctrl+Shift+I), click a cell: the Identify Results panel shows band and value and, under Derived, the clicked x, y and the column/row. Fill Table C.
  5. Style without changing values. Properties → Symbology: land cover → Paletted/Unique values with colour and label per code; elevation → Singleband pseudocolor. Under Transparency, note the reported No data value and set Display no data as a loud colour. Re-open Information and re-identify: unchanged. Leave the Symbology tab’s Resampling at Nearest neighbour — that setting is display-only (“when you zoom in and out”) and must not be confused with the data resampling below.
  6. Statistics. Processing → Toolbox → Raster analysis → Raster layer statistics, band 1. Reports min, max, range, sum, mean, std dev. Its documentation does not say whether NoData is excluded — read the mean and use 13.6 / 12.75 / −612 to work out which rule it applied. Record the rule.
  7. Resample copies. QGIS has no tool called “Resample”. Use GDAL → Raster conversion → Translate (convert format) and type in Additional command-line parameters: -tr 50 50 -r nearest for the nearest copies and -tr 50 50 -r bilinear for the bilinear copies (-tr = target cell size in the raster’s units; -r = resampling method). Save each as .tif with the Route A names. (If your rasters had a CRS, Warp (reproject) offers the same choices via “Resampling method to use” and “Output file resolution”; it is not used here because Warp’s target CRS defaults to EPSG:4326 and the fixture has none.)
  8. Inspect, read, compare exactly as in Route A steps 9–11. Raster layer unique values report gives per-value counts for the land-cover outputs. GDAL’s bilinear and Esri’s bilinear are the same arithmetic for interior cells at a 2× resample; edge and NoData-neighbour behaviour is software-specific in both — record, don’t assume.

What differs from ArcGIS Pro, in one breath: resampling is reached through a conversion tool with a command-line option; the display resampling control lives in Symbology and is a different thing; the statistics tool’s NoData rule is undocumented; method names differ; unknown-CRS handling is a project setting rather than a warning.

A correct submission…
  • has Table A for all six rasters, with the outputs showing cell size 50 and the same extents as their sources;
  • shows every Table A property identical before and after the styling step;
  • reports the elevation mean as 13.6 with the rule stated, and names what 12.75 and −612 would have meant;
  • has every record row filled — an empty one is a fail, because the point of those rows is to observe;
  • names nearest neighbour (or majority) for land cover and an interpolating method for elevation, with the numerical reason for each;
  • states that the 50 m outputs contain no information the 100 m sources did not.

4.7.7What you hand in

  1. Table A for all six rasters, with a “where did the meaning come from” note per raster (“this tutorial’s dictionary”; “none in the file”).
  2. Table C with every observed cell filled, including the four record rows (export the checker below or copy it by hand).
  3. Statistics log: min/max/mean for six rasters; for the two elevation rasters, the one-sentence statistic with rule and coverage.
  4. Before/after evidence for the styling step and the sentence about what changed.
  5. The explanation from the last step.
  6. A discrepancy list: every place a control, label or behaviour differed from the box, plus your software version (Help → About).
