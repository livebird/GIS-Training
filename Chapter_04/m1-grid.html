Module 4.1 · General GIS principle

The raster model: a grid of numbers

Before you look at a single satellite photo, look at nine numbers in a 3 × 3 grid. If you understand these nine, you understand every raster — an elevation model, a rainfall map, a Google-Maps-style satellite image.

In this module you will

  • Learn rows, columns, cells and values by clicking on a small grid.
  • See the difference between objects with edges (Chapter 3) and a surface sampled into squares.
  • Decide, question by question, when a grid is the right choice and when it is not.

4.1.1Rows, columns, cells, values

A raster is a grid: a table of cells (also called pixels) arranged in rows and columns. Every cell holds one value that describes the piece of ground the cell covers. There are no points, no lines, no separate records — just numbers in squares, plus a small header that says how big a cell is and where the grid sits.

Try it

Click any cell. Then press Show as a picture to see what a GIS does to these numbers by default.

Click a cell.

Rows are counted from the top. Row 1 is the northern edge once the grid is placed on a map. Keep this in mind for module 4.3.

Three things are already true here and stay true for every raster:

  1. A cell has an address, not a name. “Row 2, column 3” is the cell holding 30. There is no ID field. Its position is its identity.
  2. Every cell has a value — or is clearly marked as empty. The middle cell is not “blank by accident”. It is NoData: a stated “we do not know”. Module 4.4 is all about this.
  3. The grid has a direction. Rows are listed top to bottom. Software usually numbers them from 0; in this tutorial we say “row 1, row 2…” like a person reading a table.
Everyday picture

Think of a rangoli grid or an Excel sheet: the sheet is made of equal boxes, each box holds one value, and you find a box by its row and column. A raster is that sheet, laid on the ground, where each box covers a real patch of land.

Developer view

A raster band is simply a 2-D array, values[row][col], and the file is that array plus a small header. Indexing, “same shape”, memory cost — all as you expect (a 10,000 × 10,000 grid is a hundred million cells). Where the comparison stops: an array in memory does not know where it is in the world, and its numbers are not colours. A raster’s header turns each index into a real place with an area, and its numbers are measurements or codes that only become colours at display time.

Common mistake

“A raster is just an image.” A satellite photo is one kind of raster — but so is a rainfall grid, a flood-risk grid and an elevation grid. If you think “image”, you will try to “get the height” from a screenshot of a map, which holds only colours. Think “grid of numbers” instead.

4.1.2Objects with edges vs a surface cut into squares

Chapter 3’s vector model stores objects: a streetlight is a point, a road is a line, a ward is a polygon, and each has its own record. That works when the thing has edges. It fails for things that vary everywhere — the height of the ground, monsoon rainfall, how green the land is. There is no line on the ground where “height 13 m” stops and “height 14 m” begins.

A raster handles this by sampling: cut the area into equal cells and give each cell one value that stands for that patch. Two kinds of value are possible, and our practice town has one of each:

Continuous — a measured quantity

Each number is a height in metres above a made-up zero level (TD-0). The number 13 means 13 metres. Averages, differences and “higher than” all make sense.

Categorical — a code for a class

Each number is a code: 0 = water, 1 = built-up, 2 = vegetation, 3 = bare ground. The number 2 does not mean “two of something”. You can count cells per class; you cannot average them (module 4.5 shows what goes wrong if you do).

4.1.3Which model fits? Ask the question, not the thing

Beginners often learn a shortcut: “vector for objects, raster for everything else”. It is wrong in both directions. Points and rainfall can both be stored either way. What decides is the question you are asking.

Three signs a raster is the wrong choice

  1. You need the identity of a thing. A cell with code 1 does not know which building it is part of.
  2. You need exact edges. A raster’s edges are cell edges. The pond in our grid is seven square cells; the real pond is not square.
  3. The object is smaller than a cell. Streetlight SL-0113 sits inside a cell classified vegetation. The light has not vanished — a 100 m cell just shows whatever covers most of it. If the object is smaller than the cell, it may not exist in the raster at all.

Three signs vector is the wrong choice

  1. The thing has no edges. Height, rainfall, noise level.
  2. You would need thousands of tiny polygons to capture how the grass changes colour across a field.
  3. The input is a sensor image. A drone or satellite photo only comes as a raster.
