5.8.3Part A — the diagnosis table

Work through the steps, then fill the table. Press Check my table for feedback on the classification columns; the evidence and remaining-questions columns are yours to write and are checked by the instructor.

  1. Case A. Which column is which? Are all values inside the expected area? Convert one point to DMS and back (5.2). Is “the app says WGS 84” plus the header enough to name a CRS code?

  4. Case D. Try each hypothesis in the panel below and record whether the numbers alone exclude it. Can the CRS be determined? What evidence would resolve it, and who would you ask?

5.8.4Part B — optional software inspection not execution-tested

Load Case A only (the case whose CRS you documented) and inspect data CRS versus map CRS. Do not transform anything. Do not load Case C or Case D: C would draw in the wrong place and tempt you to “fix” the numbers; D would prompt a CRS-assignment dialog — exactly the guess this chapter forbids. Both are repaired, with evidence, in Chapter 6.

  1. Open a project with a new map that already has a web basemap. Before adding data, open Map Properties › Coordinate Systems and record the map CRS under Current Map Coordinate Systems. (Expected from the documentation: WGS 1984 Web Mercator (auxiliary sphere), WKID 3857, because the basemap was the first layer.)
  2. Add caseA_requests.csv and run the XY Table To Point tool (available at all licence levels). X Field = lon, Y Field = lat, leave Z Field empty, Coordinate System = the geographic WGS 1984 system (WKID 4326) — the tool’s documented default. The tool itself labels X “longitude” and Y “latitude”; the column names are your evidence for the mapping.
  3. Open the output layer’s Properties › Source › Spatial Reference and record the data CRS on a coordinate card.
  4. Back in Map Properties › Coordinate Systems, expand the Layers folder and confirm the new layer sits under a different heading from the basemap.
  5. Hover over one point and read the coordinate display at the bottom; change the display units from the arrow beside it and read again. Record both readings and explain in one line why neither changed the stored data.
  1. Start a new project; note the project CRS on the status-bar button (it depends on the CRS for projects option and on whether a basemap was added first).
  2. Layer › Add Layer › Add Delimited Text Layer; under Geometry Definition choose Point coordinates, X field = lon, Y field = lat, Geometry CRS = EPSG:4326.
  3. Right-click the layer › Properties › Source and read Assigned Coordinate Reference System (CRS).
  4. Open Project › Properties › CRS and compare with step 3.
  5. Read the status-bar coordinate box while hovering over one point; record it together with the project CRS.

Deliverables

  1. The diagnosis table (four rows, seven columns) as a Markdown or spreadsheet file, with an evidence column and a remaining questions column added.
  2. The hand arithmetic for one DMS/DD conversion and the two Case B estimates, step by step.
  3. The Case D hypothesis list with one-line reasons and the evidence request.
  4. A summary paragraph: which case cannot be resolved from numbers alone, and the difference between “consistent with” and “established”.
  5. Part B only: two coordinate cards (map CRS, data CRS), the two pointer readings with their display units, and the one-line explanation.

Scoring: reasoning 30 %, correctness 30 %, verification 25 %, documentation 15 %. A table with correct labels and no evidence column scores at most 45 %.
