Module 6.8 · Guided lab · ArcGIS Pro (primary) or QGIS

Lab: two layers, two coordinate systems, one honest answer

You receive the wards in degrees (EPSG:4326) and the requests in UTM metres (EPSG:32643). Inspect both, make an analysis-ready copy by transforming (not relabelling), measure one distance and one area with units, write a log, and get someone else to spot-check you.

Objective

  • Produce wards_e6_utm and requests_e6_utm in EPSG:32643, with the originals untouched.
  • Report Q1–Q2 distance and Ward A area (flat and geodesic) with method, units and rounding.
  • Fill the two worksheets, keep a log, and hand-check one number.
Read this first

The software steps below were written from the official ArcGIS Pro 3.7 and QGIS 3.40 documentation and have not been run by the author. The expected numbers are formula results (module 6.7). Your instructor must reproduce them in the installed software before you rely on them (chapter document, Instructor Appendix I.3) — accept differences up to 0.01 m for lengths and 1 m² for areas.

6.8.1–6.8.2Prerequisites and software

  • Modules 6.1–6.7; Chapter 5’s CRS checklist; ability to create a text file.
  • Primary route: ArcGIS Pro 3.x, any licence level. The tools used — XY Table To Point, Project, Define Projection (diagnostic only) and Calculate Geometry Attributes — are available at Basic, Standard and Advanced according to their pages. No ArcGIS Online sign-in, credits or downloads are needed.
  • Alternative: QGIS Desktop 3.40 (section 6.8.8 below). No software at all: do the worksheet parts on paper and use the expected values.

6.8.6Troubleshooting

  

    
GeoJSON will not add directly
Some versions add .geojson as a layer; others need JSON To Features. Either way, confirm the Source tab shows WGS 84 and log the route.

    
Points appear near the equator, far west
The CSV was read as degrees (Coordinate System left blank). Delete the output and re-run step 4 with WKID 32643.

    
Wards shifted by tens of metres
Check Map Properties ▸ Transformation: a transformation was applied where none belongs, or a layer’s label is not WGS 84. In this fixture there must be none.

    
Values differ by a few millimetres
Different Transverse Mercator implementations differ at that level; accept up to 0.01 m. Larger differences mean a different CRS definition, zone or method.

    
Calculate Geometry refuses flat area
The input is geographic or Web Mercator. Use wards_e6_utm, or pick the geodesic property.

    
Measure tool shows only Geodesic
The map CRS is geographic; Planar needs a projected map. Set the map to EPSG:32643 for this measurement, or compute from the coordinates (step 10).

6.8.8QGIS alternative (equivalent exercise; not execution-tested)

  
Same concepts, different tools — and one important difference in how the measurement method is chosen. Same expected values.

  
    
    
  1. Inspect. Text editor first, as in step 1. Add wards_e6.geojson via Layer ▸ Data Source Manager ▸ Vector; check its CRS under Layer Properties ▸ Source. Note the project CRS in the status bar (a new project uses EPSG:4326 unless set to take the first layer’s CRS — record which applies).
    2. 
    
  2. Load the CSV with Data Source Manager ▸ Delimited Text: Geometry = Point coordinates; X field E_m; Y field N_m; Geometry CRS = EPSG:32643. Confirm alignment; write the same “aligned, not analysis-ready” note.
    3. 
    
  3. Diagnostic. On a duplicate of the points only, run Assign projection with Assigned CRS = EPSG:4326; watch it leave the town; delete it. (Not Define Shapefile projection, which writes to disk.)
    4. 
    
  4. Transform. Run Reproject layer on the wards with Target CRS = EPSG:32643. Check the Coordinate Operation field shows no datum operation; log it. Save as wards_e6_utm.
    5. 
    
  5. Measure — read the Info panel. Open Project ▸ Properties ▸ General ▸ Measurements and record the Ellipsoid. With the default (an ellipsoid), Measure Line gives the ellipsoidal distance even on a UTM layer: expected Q1–Q2 = 664.46 m. Switch the dialog to Cartesian, or set the ellipsoid to None / Planimetric with the project in EPSG:32643, to get the flat value 664.20 m. Copy the dialog’s Info text into your log. This is the QGIS lesson: the project’s ellipsoid setting, not the layer, chooses the method.
    6. 
    
  6. Area. Run Add geometry attributes on wards_e6_utm twice: Calculate using = Layer CRS (expected ≈ 1,134,426 m²) and Ellipsoidal (expected ≈ 1,135,335 m²). Log both, the ratio, and the reason.
    7. 
    
  7. Deliverables as above, with QGIS and PROJ versions recorded.
    8. 
  

  
Not claimed: that QGIS and ArcGIS Pro give bit-identical numbers, or that QGIS’s ellipsoidal area matches Esri’s shape-preserving one beyond the 1 m² tolerance. The instructor records what was actually observed.
