ArcGIS Pro: the desktop authoring product

Where a skilled person creates, edits, styles and analyses data. And the one fact that trips up every developer: a project file points at data; it does not contain it.

In this module you will

  • Learn what ArcGIS Pro is for and its basic vocabulary: project, map, layout, table, Contents pane, Catalog pane, connection.
  • See what happens when you email a project file to a colleague.
  • Tell changing the data from changing how it looks.

2.2.1What ArcGIS Pro is for

Esri’s documentation calls ArcGIS Pro “a full-featured professional desktop GIS application” for exploring, visualising and analysing data, making 2D maps and 3D scenes, and sharing work to ArcGIS Online or ArcGIS Enterprise. In the language of module 2.1 it is R1 — desktop authoring. It runs on a workstation; on first launch you sign in with an ArcGIS Online or ArcGIS Enterprise organisation account. It is a licensed commercial product — which licence you have is a question for your administrator, not this page.

Developer view

A project is like an IDE workspace or solution file: it records what you were working on, how the windows were arranged, and where to find the sources — and, just like a workspace, it does not contain the source itself. Where the comparison stops: a workspace points at code you wrote; a GIS project points at data that other people and tools may change while your project is closed. A project can go stale in a way a workspace rarely does.

Optional: a short guided look (ArcGIS Pro 3.7 documentation edition; not execution-tested)
  1. Start ArcGIS Pro and open the instructor’s Chapter 1 project (a .aprx file). Sign in if prompted.
  2. Look at the Contents pane: it lists the map’s layers — Requests, Assets, Roads, Wards — in drawing order. This is presentation.
  3. Right-click the Requests layer and open its Attribute Table (confirm the label in your installed version). A table view of the same dataset.
  4. Open the Catalog pane. Expand Databases and Folders. These are connections: pointers to where datasets are stored.
  5. Open the Requests layer’s properties and find Source. It shows the path to the dataset. Write it down.
  6. Close the project without saving. Nothing you did changed the data.

QGIS equivalent: a .qgz project file also stores references, not data. The Layers panel ≈ Contents; the Browser panel ≈ Catalog; a layer’s source path is under Properties → Source. QGIS warns of “unavailable layers” when a file has moved — the same broken-link idea as below. Panel names differ; the idea is shared.

2.2.2A saved project is not the datasets it points at

Esri says it directly: a project “includes connections to folders, databases, toolboxes, and servers that contain data”; it is “a single file with the extension .aprx”; and map files store “the path to each layer’s data source, but not the data”. A colleague who receives the file “must have access to the data” separately.

Consequences for a developer
  • A project in version control captures presentation and structure, not data. Data needs its own backup and owner.
  • “Send me the project” is rarely enough. Ask for the project and where its data is — or a package containing both.
  • When a layer shows as broken, check the source path first, not the data.
Misconception

“Saving the project saves my edits.” In ArcGIS Pro, edits to data are saved separately from the project. Someone who believes they are the same can lose data edits — or believe that not saving the project undoes edits already written to storage. Durable rule: project state and data state are saved separately; know which one you changed. (The exact prompts are version-specific; your instructor will demonstrate on a disposable copy.)
