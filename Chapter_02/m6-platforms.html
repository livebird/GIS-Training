Module 2.6 · General principle

The same five jobs on other platforms

Compare roles, not brands. Ask “which job does this product do?” before “which Esri product does it replace?” — because the honest answer to the second is usually “part of one, and none of the others”.

In this module you will

  • Place OpenLayers and Mapbox by job.
  • Place QGIS, PostGIS and GeoServer by job — and find the gap.
  • Label tasks as shared GIS knowledge or platform-specific implementation.

2.6.1OpenLayers and Mapbox

OpenLayers R5 · browser library

Describes itself as “a high-performance, feature-packed library for all your mapping needs” that “makes it easy to put a dynamic map in any web page” and “can display map tiles, vector data and markers loaded from any source” — tiles from several providers, OGC standard map services (OGC = Open Geospatial Consortium, the body that publishes open GIS standards), and file formats such as GeoJSON, TopoJSON, KML and GML (Chapter 7). Free and open source, under a permissive licence (2-clause BSD).

Job: the browser application layer — the same role as the ArcGIS Maps SDK for JavaScript. It says nothing about where tiles or data come from (R2, R3), who may see them (R4), or who authored them (R1). Esri itself lists OpenLayers among libraries that can consume ArcGIS services: it can be the front end of an Esri stack, an open-source stack, or a static file.

Mapbox R5 + hosted R3/R2 products

Presents product families rather than one library: Maps (Mapbox GL JS for the web, mobile SDKs, Studio for map design, static map images, a service that cuts data into map tiles), Navigation, Search (geocoding — turning an address into a map position — and address autofill), Data (traffic, movement, boundaries), and a self-hosted option.

Jobs: a browser library (R5), hosted tile and data services (R3, and R2 for the datasets Mapbox itself provides), and a design tool for map styles (a slice of R1 for cartography — not for editing your own asset data). This page takes no position on Mapbox pricing, licensing or terms; they change.

Developer view

“We’ll use OpenLayers” is like “we’ll use React”: it names the front-end library and says nothing about the database, the API, authentication or hosting. “We’ll use Mapbox” is more like “we’ll use Firebase”: a vendor’s bundle of SDKs and hosted services chosen together. Where it stops: in a GIS the dataset is usually the organisation’s long-lived asset, so “who holds the authoritative copy, and can we take it with us?” weighs more than it does for a web app’s session data.

OpenLayers is a browser library. Where will the request data be stored and edited? How will it be served to crews but not the public? How will crews edit offline on phones? Who operates the servers that implies?

R4 is the gap

QGIS + PostGIS + GeoServer give you authoring, storage and services. None of them is a portal with items, groups, sharing levels and member roles. Teams going this route add a catalogue product, a login system (identity provider) and a good deal of custom connecting code (“glue”) — or accept that “sharing” means file paths and server URLs passed around by hand. That is a legitimate choice for some organisations; it is not a free one, and it is exactly the kind of omission the five-job model exists to expose.

Misconception

“QGIS is free ArcGIS Pro, GeoServer is free ArcGIS Server, PostGIS is a free geodatabase.” An architecture gets proposed with three products and one missing job; or a data-model feature a geodatabase enforces (Chapter 8) is assumed to exist in PostGIS by default and silently does not. Compare roles, then check each capability the requirement needs.

2.6.3Shared knowledge or platform-specific?

For each task, is the knowledge needed to do it well shared GIS knowledge (it transfers unchanged to any platform) or platform-specific implementation (you would relearn it on another product)? Most tasks have both; sort by the dominant part. Worked example first: “Decide that a ward should be a polygon rather than a point” → shared, because it depends on the question the data must answer, not the software; the platform-specific part is only the geometry type’s name and storage format.
