Module 2.4 · Platform-specific (Esri)

ArcGIS Enterprise: the version you operate

Same content ideas as ArcGIS Online — items, groups, web maps. Completely different responsibility: your organisation owns the machines, the upgrades, the backups and the 3 a.m. outage.

In this module you will

  • Explain why Enterprise is not “ArcGIS Online installed locally”.
  • Place Portal, Server, Data Store and Web Adaptor by the job each does.
  • Tell using a platform from operating one.

2.4.1An organisation controls its deployment — and its consequences

Esri describes ArcGIS Enterprise as “the foundational software system for GIS” that organisations deploy on infrastructure they control: public cloud, private cloud, or on-premises physical or virtual machines; small single-machine or large multi-machine; connected to the internet or disconnected from it. The same page makes the organisation responsible for the choice of infrastructure, its scale, and its strategy for uptime and data-loss prevention.

Look closely

The top halves look the same. The bottom halves do not.

ArcGIS Online

items groups members & roles web maps hosted layers apps
Operated by Esri. Machines, storage, network, patches, upgrades, backups, monitoring, scaling: Esri’s job. Needs internet. Metered by credits.

ArcGIS Enterprise

items groups members & roles web maps hosted layers apps
Operated by your organisation. You choose the infrastructure, install, upgrade, patch, back up, monitor, restore, and scale. Can run disconnected. Can serve data from your own databases without copying. Licensed per deployment.

Why the top halves match: Esri notes that web maps “adhere to the same web map specification” across ArcGIS, so a map made in ArcGIS Pro can be edited in ArcGIS Online or in a portal — and that Enterprise “connects with ArcGIS Online” to share content. The two are designed to work together, not as rival editions of one thing.

The change of job description

Building an app against ArcGIS Online means writing to an API and administering content. Building the same app against ArcGIS Enterprise means that someone in your organisation also owns servers, certificates, backups, upgrades and outages — and if that someone is you, those tasks now sit beside your feature work.

Developer view

ArcGIS Online : ArcGIS Enterprise ≈ a managed database service : running the same engine on your own servers. Similar interface, very different operations. Where it stops: Enterprise is a system of several cooperating components (below), not one engine — and the two are meant to coexist and share content, not to be alternatives.

Two confusions to avoid

Enterprise can serve data you already have. Unlike a hosted layer, an ArcGIS Server service can reference data registered in your own database or file location. Publishing from ArcGIS Pro offers exactly that choice: copy all data so it becomes “managed by ArcGIS”, or reference registered data that stays where it is. Whether a service copies or references is something to ask, never assume.

“ArcGIS Data Store” is a product, not a synonym for “our database”. It is the managed storage behind hosted layers in an Enterprise deployment. Your PostgreSQL, SQL Server or Oracle database is a different thing, registered with ArcGIS Server as a data source (Chapter 7).

Release-specific detail deferred. The exact base-deployment list changes between releases. For the record, the 11.4 documentation names Portal for ArcGIS, ArcGIS Server as the hosting server, ArcGIS Data Store (relational + object store) and two Web Adaptors, installable “across one or more machines, any of which can be physical, virtual, or cloud machines”. Re-read the page for whatever release your organisation installs.

What you must do now is recognise it: when someone says “the request service is down, can you fix it?”, you should know that is infrastructure work, needs different access and skills, and that in ArcGIS Online the same request would go to Esri, not to you.

Misconception

“Enterprise means more features.” A team picks Enterprise to “unlock” something, then discovers the practical difference is a set of operational obligations nobody planned for. Feature differences exist and change by release; the responsibility difference is permanent.
